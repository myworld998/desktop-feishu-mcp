# 验证范围与发布检查

## 当前整理环境的限制

本轮在受限 Windows 工作目录内整理文件：原安装的 Python、Node、CLI 不可执行，尝试调用本机 Python 得到“拒绝访问”；也不能下载临时 Python。因此本轮不声称完成 Python 运行测试、飞书真实收发或跨平台自启实测。以下回归测试与 CI 已提供，需要在具备运行环境的机器上执行并记录结果。

指定渠道的 Claude CLI 独立审阅也无法在当前沙箱启动；本轮静态自查不等同于独立 code-reviewer 审阅。

原版本的卡片 form / name 编码 / 更新方式来自已有实现，本次保留。新增配置与 setup 逻辑需要离线测试通过后，再做真实飞书回归。不要把生成服务文件等同于已安装或已验证开机自启。

## 离线验证

```sh
python -m unittest discover -s tests -v
python package.py --check
python package.py
```

测试覆盖配置优先级与项目相对路径、显式 Node/JS 探测、MCP initialize/tools/list/通知、CLI 异常返回、卡片 form 不变量、灰色禁用更新、回调 ID 安全与原子结果写入，以及生成 MCP 配置和各平台自启文件的结构。测试使用临时配置与临时文件，不读取 CLI 凭据，不联系飞书。

`package.py --check` 检查完整项目内非忽略文件是否含真实形态的用户/会话/应用标识及个人绝对路径，并拒绝未纳入公开文件清单的文件。它不是通用密钥扫描器，发布前仍要人工审查。`package.py` 只打包清单内文件到 `.local/dist/`，不会打包整个工作目录。

GitHub Actions 在 Windows/macOS/Linux 与 Python 3.10/3.12 上运行离线测试和扫描。工作流文件存在不表示 CI 已实际运行；本轮没有创建、提交或推送仓库。

## 飞书实测清单

- 正确的独立 app/profile，确认机器人和后台回调、权限均已发布。
- `doctor` 通过，`verify` 消息读取成功且长连接 ready。
- 无快捷选项时，输入意见并提交；空意见提交；多个快捷选项；选项含中文和下划线。
- 卡片保留问题与表单，回复后标题变灰、按钮和输入框禁用、附上结果。
- 配置允许用户后，其他用户点击不被接受；目标会话以外的回调被忽略。
- 两个 MCP server 进程的请求互不串话；一个进程的请求仍同步串行。
- 不点击时超时；卡片发送失败才走文字回退；多个未完成问题不使用文字回退。
- 客户端重启后 initialize/tools/list 正常；超过客户端默认超时的等待需验证客户端设置。
- 手动启动与自启服务分别检查 ready；禁用服务后确认没有重复 listener。

将实际验证日期、操作系统、Python / CLI 版本、结果写入发布说明。只记录版本和通过/失败，不附真实标识、卡片内容、原始回调或认证输出。
